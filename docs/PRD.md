## 1. 背景与目标

**现状**
素材文件夹里已经有一套素材，但靠文件名人工对应，用起来很割裂：

| 类型 | 例子 | 说明 |
|---|---|---|
| 原曲视频 | `[🎵] 月光 Lo-fi Remix （原唱：张三）.mp4` | 命名不统一 |
| 伴奏 | `月光 Lo-fi Remix - 伴奏.wav / .mp3` | 同一首歌 wav、mp3 各一份 |
| 人声 | `月光 Lo-fi Remix - 人声.wav` | 分离出来的原唱人声 |
| 外部混录 | `月光.m4a` | 用 iPhone 同时录下自己的声音和 Mac 外放的伴奏，人声和伴奏混在一起 |
| 歌词 | 无 | 目前没有 LRC 文件 |

播放伴奏用系统播放器，歌词另开窗口看，没法同步滚动，也没法边听伴奏边带一点原唱做引导。

**目标**
一个桌面应用：**选歌 → 放伴奏 → 歌词跟着滚动**，用来练唱、录唱。

**不做（v1）**
- 在线曲库、在线抓歌词
- 人声分离（已经用外部工具做好了）
- 应用内播放原曲视频（mp4 只做关联，需要时用系统播放器打开）
- 逐字高亮（卡拉 OK 式填色），逐行高亮已够用
- 账号、云同步、多人使用
- Windows / Linux

## 2. 使用场景

| # | 场景 | 描述 |
|---|---|---|
| A | 练唱 | 从曲库选一首歌，放伴奏，看滚动歌词跟着唱；不熟的地方开一点原唱人声带着唱，某段反复循环 |
| B | 做歌词 | 新歌放进文件夹后，粘贴歌词纯文本，边听边按空格打时间轴，生成 LRC |
| C | 录唱 | 戴耳机跟着伴奏录自己的声音；不满意的段落单独补录；同一首录好几遍，挑最好的一遍 |
| D | 修音 | 对选中的那一遍录音自动修正跑调（以原唱人声为参考），加点效果，导出成品 |

## 4. 前台（用户界面）

### 4.1 曲库页（首页）
- 左侧歌曲列表：歌名、原唱、版本（如 Lo-fi Remix）、状态标记（有伴奏 / 有人声 / 有歌词）
- 缺歌词的歌曲显示「去打轴」入口
- 双击进入演唱页
- 顶部：搜索框（P1）、重新扫描按钮

### 4.2 演唱页（核心页面）
- **歌词区**（占主要面积）：当前行居中放大高亮，上下各显示 2–3 行；随播放平滑滚动；点击任意行跳转
- **控制条**：播放/暂停、进度条（显示时间）、上一句/下一句
- **混音面板**：伴奏音量、引导人声音量（默认 0，即纯伴奏）
- **歌词偏移**：± 按钮，每次 50ms，保存到该歌曲
- P1：A-B 循环、升降调、录音按钮、全屏
- **音高窗口**（0.2.2）：歌词下方一条，原唱音高曲线（人声分轨分析）跟着播放滚动，前 4 秒后 6 秒，竖线 = 耳朵听到的位置；录音栏打开时叠加麦克风实时音高（折到原唱八度；前后 0.1 秒内和原唱差 ≤ 50 音分 = 蓝，否则橙）；右上「音高」开关，记在设置里；没有人声分轨时不显示
- **导出的成品**（0.2.2）：录音列表下面列出「录音/歌名/导出」里的 wav / m4a，可播放、打开文件夹

**快捷键**

| 键 | 功能 |
|---|---|
| 空格 | 播放 / 暂停 |
| ← / → | 后退 / 前进 5 秒 |
| ↑ / ↓ | 上一句 / 下一句 |
| V | 引导人声开 / 关 |
| F | 全屏（P1） |

### 4.3 打轴编辑页
歌词来源已确认：**全部靠手动打轴**，所以这个编辑器要做得顺手。

**流程**
1. 粘贴歌词纯文本（每行一句），自动去掉多余空行
2. 点开始，默认播放**原唱人声轨**（比听伴奏更容易听出每句从哪开始），可切换成伴奏或两轨一起
3. 每句开唱时按空格，记录时间到这一行，焦点自动跳到下一行
4. 间奏处按 Enter 插入一个空行时间点，歌词在间奏时清屏
5. 打错了按退格撤销上一句，或在列表里直接改时间
6. 预览模式：按打好的时间轴回放检查
7. 保存为同名 `.lrc`，放在歌曲文件旁边

**辅助功能**
- **放慢播放**：0.5x / 0.75x / 1x 可切换，快歌打轴更准（打轴时允许音调跟着变，实现简单）
- **人声波形**：编辑器下方显示原唱人声波形，每句开头的位置一眼看得出；打下的时间点以竖线标在波形上，可以直接拖动
- **逐行微调**：选中一行，⌥ + ← / → 每次 ±50ms，并自动从这行前 2 秒播放确认
- **扣除耳机延迟**：AirPods 下听到的声音比实际晚约 0.2 秒，按下空格记录的时间会自动减去校准过的延迟；再额外减去一个可调的「反应时间」（默认 100ms）
- **打轴吸附（P1）**：按下的时间自动吸到前后 300ms 内最近的人声起音点，基本不用再微调

### 4.4 录唱（在演唱页里进行）

**为什么要在应用里录**：现在的做法是 iPhone 同时录下人声和 Mac 外放的伴奏（`月光.m4a`），人声和伴奏混在一起，还带着房间回声，没法单独修音、也没法换伴奏重混。应用里录的是干净的干声（伴奏只在耳机里），后面的对齐、修音、混音都建立在这个基础上。已有的外部混录作为「外部录音」关联到歌曲，可以试听对比；想修这类录音要先做人声分离（P2）。

**录音设备：MacBook 自带麦克风**（已确认）

自带麦克风带来的几个约束，决定了下面的设计：
1. 外放的伴奏会直接被麦克风录进去 → **必须戴耳机**
2. 蓝牙耳机（AirPods 等）有 150–250ms 延迟 → 耳返没法用，录音对齐要单独校准
3. 自带麦克风离嘴远、会录进房间回声和底噪 → 降噪默认开启，录音环境给提示

**录之前**
- 点「录音」，控制条上方展开录音准备栏：输入设备（默认 MacBook 麦克风）、实时电平表（太小 / 合适 / 爆音三色）
- **耳机检测**：自动识别当前输出设备
  - 扬声器外放 → 红色提示「请戴耳机，否则伴奏会被录进去」，仍允许录（比如只想清唱）
  - 有线耳机 → 可开耳返（自己的声音实时回到耳机里）
  - 蓝牙耳机 → 耳返自动关闭并说明原因（延迟太大会干扰唱歌）；开放式耳机本身能听到自己的声音，影响不大
- **主力耳机：AirPods**（已确认），专门处理三件事：
  - **只用 MacBook 麦克风录**：AirPods 的麦克风一旦被打开，蓝牙会切到通话模式，耳机里的伴奏音质会突然变差（变闷、变单声道），录到的人声也只有电话音质。应用录音时固定指定 MacBook 麦克风，不跟随系统默认输入；如果手动选了 AirPods 麦克风，弹窗说明并阻止
  - **用通透模式代替耳返**：AirPods Pro / Max 打开「通透模式」，能零延迟听到自己的声音，录音准备栏里提示一句；普通 AirPods 是开放式的，本来就听得到
  - **建议关闭空间音频**：避免伴奏声场被处理，第一次录音时提示
- **跟拍校准**（每种耳机首次使用时做一次，结果按设备记住；AirPods 重新连接后提示「要不要快速再校准一次」）：耳机里播放 8 下节拍，跟着每一拍对麦克风说「嗒」，自动算出延迟。比播提示音自测更可靠，因为蓝牙延迟只有戴着耳机才测得出来
- **录音环境提示**（首次显示，可关闭）：离电脑 30–50cm、保持距离不变、电脑别放在硬桌面正中、关空调风扇、录前先录 3 秒安静环境用于降噪
- 选范围：整首，或者用 A-B 选一段做补录

**录的时候**
- 开始前自动先录 2 秒环境底噪（这时安静不要出声），作为降噪参考
- 3 秒倒数（或从选区前 2 小节开始预备播放），到点自动开始录
- 歌词照常滚动；进度条上实时画出录音波形；红色录音指示
- 空格停止
- 录的时候可以按 ±5 秒、点歌词跳行（比如跳过前奏）或暂停：每段连续播放各存成一段，分别和伴奏对齐；往回跳重唱的部分以后录的为准
- **防忘记停**：从开始录算起超过 歌长 + 30 秒自动停止并照常保存，提示「录音比歌长了 30 秒，已自动停止」
- **崩溃恢复**：上次没录完的 `.wav.part` 打开这首歌时自动恢复成一遍；但超过歌长 1.5 倍且至少多出 60 秒（不知道歌长时超过 15 分钟）的不恢复，标成「异常录音」，在「资料」检查页里列出（大小、多长），只能一键移到废纸篓，从不自动删（资料清单 §5-9）

**录完之后**
- **自动对齐**：把这一遍和原唱人声比对，算出整体偏差，自动把录音再挪准一点（兜底蓝牙延迟的小幅波动）；偏差超过 50ms 时提示，并提供手动微调滑杆（±100ms，边拖边听）
- 自动存为 Take 1、Take 2…，右侧 Take 列表：试听、改名、标星、删除
- 默认回放「我的声音 + 伴奏」，按 V 在同一位置切换成「原唱 + 伴奏」对比
- 补录的段落自动替换进这一遍里对应的位置（保留原版本可撤销）
- 选中一遍点「去修音」

```
│ 钢琴卷帘   ── 灰线：原唱音高                           │
│           ── 彩线：我的音高（跑调 > 30 音分标红）       │
│           ── 绿线：修后音高                            │
├──────────────────────────────────────────────────────┤
│ 波形                                                  │
├──────────────────────────────────────────────────────┤
│ 参考[原唱/音阶]  调[自动检测]  强度[━━●━]  速度[━●━━]   │
│ [应用修音]  [修前 / 修后]  效果[干净|流行|温暖]  [导出]  │
└──────────────────────────────────────────────────────┘
```

**自动修音**
- 参考来源：
  - **原唱人声（推荐）**：每首歌都有分离好的 `人声.wav`，提取原唱的旋律作为目标音高，修得最准
  - **调式音阶**：没有原唱参考，或者自己改了旋律时用，把音高吸附到最近的音阶音
- 强度：0–100%，修正偏差的多少比例
- 速度：慢 = 自然，保留滑音和颤音；快 = 电音感（Auto-Tune 那种效果）
- 可以只框选某几句应用，其他保持原样
- 修前 / 修后一键切换试听
- 预期：小偏差（半音以内）修完很自然；严重跑调修完会有明显机器感，这种建议重录那一句

**效果链**
- 降噪 → EQ → 压缩 → 混响，提供 3 个预设，每项可单独开关
- 针对自带麦克风：降噪默认开；EQ 预设里默认切掉 100Hz 以下的低频（桌面震动、风扇声）
- 人声和伴奏的音量比例可调

**导出**
- 修后干声 `wav`（方便拿去别的软件继续做）
- 和伴奏混好的成品 `wav` / `m4a`（m4a 用系统自带编码器，体积和 mp3 相当，手机、剪映、TikTok 都能用）
- 存到 `<素材文件夹>/录音/<歌名>/` 下

### 4.6 手动修音（修音页的编辑模式）

和自动修音在同一个页面，钢琴卷帘切换到「音符」视图即可。推荐流程：**先自动修一遍 → 再手动修个别不满意的音**。

**音符块**
- 录音分析完后，自动切成一个个音符块：块的高度位置 = 这个音的平均音高，宽度 = 时长，块里画一条细线显示实际的音高起伏
- 背景同时显示原唱的音符块（半透明灰色），一眼看出哪个音唱偏了
- 跑偏超过 30 音分的块标红

**工具**

| 工具 | 操作 | 效果 |
|---|---|---|
| 移动音高 | 上下拖动音符块 | 改这个音的音高；默认吸附半音，按住 ⌥ 自由微调 |
| 吸附原唱 | 双击音符块 | 直接对到原唱同位置的音高 |
| 拉直 | 选中后拖滑杆 0–100% | 把音唱不稳的晃动拉平，保留颤音 |
| 颤音 | 滑杆 0–200% | 颤音收小、去掉，或加大 |
| 过渡 | 拖音符块左边缘的小手柄 | 调从上一个音滑过来的快慢 |
| 切分 / 合并 | 剪刀点一下 / 选两个按 ⌘J | 自动切错时修正 |

**吸附模式**（工具栏切换）：吸附原唱 / 吸附半音 / 自由

**试听**
- 松开鼠标后 0.3 秒内就能听到改后的效果
- 选中一个音符，自动循环播放它所在的那句
- 可以选「只听人声」或「带伴奏听」

**安全感**
- 原始录音永远不动，所有修改只是一份编辑记录
- 无限撤销 / 重做；右键单个音符「还原」，或整遍「全部还原」
- 手动改过的音符会加锁，之后再跑自动修音不会覆盖它

**快捷键**

| 键 | 功能 |
|---|---|
| ↑ / ↓ | 选中音符升 / 降半音 |
| ⇧ + ↑ / ↓ | 升 / 降 10 音分 |
| S | 切分工具 |
| ⌘J | 合并 |
| ⌘Z / ⇧⌘Z | 撤销 / 重做 |
| 双指捏合 | 横向缩放；⌥ + 捏合纵向缩放 |

### 4.7 直播模式（含一键开播、直播修音）

**一键开播**（直播面板里的「● 开始直播」）：
1. 打开歌词同步
2. 开直播声音：麦克风 → 实时修音（往原唱旋律修，原唱没在唱时吸到调内音；约 32ms 延迟）→ 人声效果，和伴奏（自动延后对齐）混好、限幅，送给叠加层页面
3. 控制 OBS（obs-websocket，随机密码）：没开就打开（自动跳过首次启动的说明窗口），建「波点」场景（旧版建的「伴奏歌词」场景和浏览器源原地改名）、放浏览器源（叠加层 `?audio=1`，声音交给 OBS），静音 OBS 自己的麦克风，填推流地址 / 推流码，开始推流
4. 面板显示直播时长、网络拥堵、我的音高 → 目标音高；「结束直播」停止推流

**三路声音互不影响**：耳机里 = app 正常放的伴奏 + 麦克风耳机孔的原声监听（零延迟）；录音 = 原声；直播 = 伴奏 + 修过的人声。没有麦克风时只推伴奏和歌词。


**目标**：用 OBS 推流（TikTok 等）时，观众能看到跟着伴奏滚动的歌词，画面干净。

**做法**：应用不自己推流，推流交给 OBS；应用负责放伴奏、提供歌词画面。
- **浏览器源（推荐）**：应用内置一个只在本机可访问的小网页 `http://127.0.0.1:17890/overlay`，在 OBS 里加「浏览器」来源填这个地址，背景透明，直接叠在摄像头画面上；应用窗口最小化也不影响
- **歌词窗口**：一个独立的小窗口，只显示歌词，背景可选绿幕 / 黑底 / 透明，用于 OBS 窗口捕获或放到第二块屏幕
- 叠加层显示当前句（大字）+ 下一句（小字），间奏时清屏；跟随播放、暂停、跳转、切歌
- **同步**：直播声音是 OBS 从应用直接采集的（不经过耳机），所以叠加层**不扣耳机延迟**，按真实播放位置走
- **样式**：字号、文字颜色、描边、是否显示下一句，在应用里调，叠加层实时更新

**直播面板**（演唱页顶部「直播」按钮打开）
- 叠加层地址 + 复制按钮、打开歌词窗口、样式设置
- 简明步骤：OBS 加「macOS 屏幕捕获 → 应用：波点」采集伴奏声音，加麦克风，加浏览器源；TikTok 推流需要账号有推流码（Stream key）
- 提醒：直播别用 AirPods 麦克风（会切到通话音质）；商业歌曲伴奏可能被平台静音

### 4.8 练声（每日基本功）

侧栏「练声」进入。app 用合成钢琴给音、实时画出你唱的音高、给每个音打分（绿 ≤ 25 音分 / 黄 ≤ 50 / 红），记录每天的成绩。

| 项目 | 怎么练 | 记录 |
|---|---|---|
| 音域测试 | 先唱一个舒服的最低音、再唱最高音，各稳住 1.5 秒 | 最低 / 最高音；之后所有练习只在这个范围里走 |
| 哼鸣热身 | 钢琴弹五度音阶（1-2-3-4-5-4-3-2-1），跟着哼，每轮升半音，到顶再降 | 每个音的准确度 |
| 气息 | 吸满气后发长长的「嘶——」 | 时长、稳定度；最好成绩 |
| 长音 | 给一个音，稳住唱 8 秒 | 平均偏差、抖动（音分标准差） |
| 音阶 / 琶音 | 五度音阶、大三和弦琶音 1-3-5-8-5-3-1、八度跳 1-8-1，逐轮升半音 | 每个音的准确度、整体音准率 |
| 听音模唱 | 随机弹一个音，你唱出来，10 题 | 平均偏差 |

- **每日练习**：一键按顺序走一遍（哼鸣 → 气息 → 长音 → 音阶 → 琶音 → 听音），约 12 分钟；也能单项练
- **进步记录**：最近 30 天的练习日历、连续天数、音准率和气息时长的变化
- 唱的音和目标差八度也算对（男女声、换声区都能练）；判分时扣掉耳机 + 麦克风延迟
- 建议戴耳机，否则麦克风会把钢琴声也收进去

### 4.10 下载视频（0.3.0）

写歌时常要下载 YouTube 上的 MV 当参考，以前在命令行里用 yt-dlp 下。现在应用里直接做：

- 入口：侧栏顶部「下载视频」。窗口关掉后下载在后台继续，按钮上显示「下载中 45%」
- 第一次用：提示要装两个工具（约 80 MB），点「下载工具」才下载，有进度、能取消
  - yt-dlp：GitHub 官方发布的文件夹版 `yt-dlp_macos.zip`，核对 GitHub 给的 SHA-256。不用单文件版 `yt-dlp_macos`：它每次运行都把一百多个库解压到新的临时文件夹，macOS 每次都要重新核对签名，光启动就要二三十秒
  - ffmpeg：PyPI 上 `imageio-ffmpeg` 的 macOS 安装包里的静态 ffmpeg，核对 PyPI 给的 SHA-256
  - 放在 `~/Library/Application Support/io.github.dylantlwu.banzou/tools/`，不依赖 PATH，不改 shell 配置
- 粘贴链接（自动读取）或回车 →「正在读取视频信息…」→ 标题、频道、时长和画质选项：
  - 兼容版（默认）：H.264 + AAC，QuickTime 能直接放；YouTube 上 H.264 最高 1080p
  - 最高画质：只在比兼容版更清楚时出现，如「2160p（VP9，要用 VLC / IINA 播放）」，文件名后面加「（2160p）」
  - 链接里的 `&list=…&start_radio=1` 忽略，只下当前这个视频
- 下载：显示「下载画面 / 下载声音 / 把画面和声音合成一个文件」和百分比，能取消（结束 yt-dlp 和它起的 ffmpeg，删掉临时文件）
- 存到素材文件夹，文件名用视频标题（中文、emoji、全角括号都保留）；同名文件已经有了就不重下，提示「之前下载过了」
- 下载完显示文件名、分辨率、编码、时长、大小；自动重新扫描曲库，告诉你挂到了哪首歌（或在「未归类」）；「播放」「在访达中显示」
- 底部显示 yt-dlp / ffmpeg 版本和「更新 yt-dlp」：GitHub 上有新版就重新下载（文件夹版不支持 `yt-dlp -U`）。YouTube 改版导致下载失败时，报错里提示先更新 yt-dlp
- 报错换成能看懂的话：私密视频、要登录确认年龄、视频不存在 / 下架、要求验证不是机器人、连不上 YouTube、链接认不出来
- 已知：yt-dlp 会提示没有 JavaScript 运行环境（deno），目前不影响下载，所以没装；以后 YouTube 改版需要时再加

### 4.11 做成伴奏（0.3.0）

下载完 MV 后常要分离出伴奏和人声，以前在另一个对话里用 Demucs 手动做。现在应用里一键完成：

- 入口：下载完的结果卡片「做成伴奏」；「未归类」里每个视频后面的「做成伴奏」；歌曲页「原曲视频」那一行（只在这首歌缺伴奏或缺人声时出现）
- 歌名：默认填猜的「歌名 歌手」（「曹格 Gary Chaw【寂寞先生】…」→「寂寞先生 曹格」，「Teddy Swims - The Door (…)」→「The Door Teddy Swims」），繁体转成简体；已经挂到某首歌的用那首歌的名字；可以改
- 生成「歌名 - 伴奏.wav」「歌名 - 人声.wav」（44.1 kHz 16 位）存到素材文件夹，曲库马上配成一首歌，视频也自动挂上；已经有的文件不覆盖，两个都有就提示先删掉或换名字；先写临时文件再改名，曲库不会扫到写了一半的文件
- 做法和之前手动做的一样：ffmpeg 抽出音频 → Demucs `htdemucs_ft`、两轨（人声 / 其他）、Apple 芯片用 GPU（mps）、float32 → 转 16 位 wav
- 进度：「抽出音频 → 分离人声 N%（4 个模型合起来算）→ 保存」，能取消、能放到后台（侧栏按钮显示「做伴奏 N%」）；4 分钟的歌约 2 分钟
- 第一次用要点「安装 Demucs」：用系统自带的 python3 在 `tools/demucs` 建虚拟环境，pip 装 demucs 和 soundfile（连同 PyTorch 约 1 GB）；第一次分离时 Demucs 自己下载模型（约 300 MB，存在 `~/.cache/torch`）；没装 Xcode 命令行工具时提示先运行 `xcode-select --install`
- 做好后提示分离出来的伴奏只适合自己练唱；「去这首歌」直接打开
- 做好后（和下载完挂上已有的歌时一样）自动给这首歌打标签、补背景，没歌词顺手找（0.3.1；没填 Claude key 不做，失败不打扰）

### 4.12 外语学唱（草稿，讨论中）

用「我的语言」学唱另一种语言的歌，比如说中文的人学日语歌《夏実》。Claude 当老师：备课、点评、答疑；声音相关的运算全在 Mac 上做。先做「教自己唱」，直播里教观众以后再说。

**语言组合**
- 设置里填一次「我的语言」（默认中文），老师始终用它讲解
- 歌曲语言：按歌词文字自动判断（假名 → 日语、谚文 → 韩语、拉丁字母 → 英语……），每首歌可以改，存进歌曲信息
- 任意组合走同一套流程，读音标注跟着歌曲语言走：日语给假名 + 罗马音，韩语给罗马音，英语只给难词标音，中文给拼音（给母语不是中文的人）

**备课（每首歌一次）**
- 第一次点「学唱」：把歌词（LRC）、歌曲语言、我的语言发给 Claude，生成课程：逐句读音、意思、难点（连读、长音、促音、吞音、气口），把歌分成几段（每段 2–4 句），标出最难的几句
- 课程存在歌旁边的 `歌名.lesson.json`（和 `.lrc` 一样，文件就是数据），应用里能改；歌词改了提示重新备课，只重做改了的句子
- 用结构化输出（JSON schema）保证格式；没装语音模型也能备课
- 歌名、人名、地名这类专有名词的读音以歌曲自带的标注为准（YouTube 标题里的罗马音，如「夏実 ⧸ Kajitsu」→ かじつ，不是常见读法なつみ；歌词本注音）；没有标注的标「读音待确认」，让我确认，不按常见读法猜

**一句一循环**
1. **听**：只放原唱人声（分离出来的那轨），可以放慢到 0.5–0.75 倍、不变调；显示原文、读音、意思、难点
2. **念**：不带旋律念一遍。语音识别 → 和歌词按读音逐字对比 → 念错的字标橙（和跑调一样避开红绿）
3. **唱**：跟伴奏唱这一句（原唱人声可以开小声带着），看音高曲线对比（现有）和每个字的早晚
4. **点评**：把念和唱的测量结果发给老师，回一两句，只说最该改的一处（「つ 你念成了 su，舌尖先顶住上齿背再放开」）

- 念对 90% 以上、音高偏差在阈值内就算「过了」，自动进下一句；也可以手动标「会了」。阈值实测后定
- 一段里的句子都过了 → 整段连唱 → 整首连唱
- 进度存 `<素材文件夹>/录音/<歌名>/learn.json`，下次从还没过的那句开始；每次念 / 唱的录音不留，只留测量结果（想留可以点「存为 Take」）

**问老师**
- 随时按住说话或打字问，比如「这句 かじつ 的 じ 为什么要拖长」
- 老师知道这首歌的课程、当前这句、你最近几次的测量结果；按歌保存对话，下次接着问
- 只发文字：歌词、课程、识别出来的话、测量结果；录音和歌曲音频不离开电脑

**老师的记性（纠正过的不再错）**
- 目标：我纠正过老师一次，以后备课、对话、念出来的话都照新的来，同样的错不犯第二次
- 记在两本笔记里，都是纯文本（Markdown，一行一条），应用里能看、改、删，也能用文本编辑器直接改：
  - **通用笔记**：配置目录的 `teacher-notes.md`，管所有歌。例：`- 歌名一律叫原文（日文汉字照写），不翻译成中文，也不按常见读法猜 〔2026-11-13 · 对话里纠正〕`
  - **这首歌的笔记**：歌旁边的 `歌名.notes.md`，只管这首歌。例：`- 读音：夏実 = かじつ（Kajitsu）〔YouTube 标题〕`
  - 读音条目用固定写法 `读音：原文 = 读音`，程序也认得（念出来、核对课程时用）
- **在哪记下**：
  1. 对话里纠正老师（「不对，夏実念 かじつ」）：老师自己判断这是纠正，提出一条笔记——写什么、记在通用还是这首歌。对话里出现一张小卡片「记住了：……」，立刻生效，卡片上能「撤销」「改」
  2. 改课程：在课程里改了读音或意思，这首歌的笔记自动加一条（同样能撤销），重新备课不会被改回去
  3. 主动要求：对话框旁边的「记住」按钮，或者直接说「记住：……」
  4. 读音待确认：备课时没把握的专有名词问我，我答了就记进这首歌的笔记
- **新旧冲突**：老师记新的时看得到所有旧笔记；和旧的矛盾就替换掉旧那条（卡片上写「改掉了：……」），同一件事只留一条
- **怎么让老师用上**：每次调 Claude，系统提示按顺序拼：老师守则（固定）→ 通用笔记 → 这首歌的课程和笔记，三段都在缓存前缀里（笔记很少变，基本不多花钱；一改，下次调用就带上新的）。守则里写明：笔记里的规矩比你自己的知识优先
- **念出来**：发给豆包前，按这首歌笔记里的读音条目替换：「夏実」换成「かじつ」再念，免得按中文念成 xià shí 或按常见读法念成 なつみ
- **备课**：备课时也带上两本笔记；备好后程序再核对一遍，课程里的读音和笔记不一致就按笔记改，并告诉我改了哪里
- 第一条（种子）：通用笔记一开始就有「歌名一律叫原文」这条；《夏実》第一次备课时从 YouTube 标题「夏実 ⧸ Kajitsu」读到 かじつ，记进这首歌的笔记
- 设置的「AI 老师」下面有「老师笔记」，列出通用笔记；每首歌的笔记在学唱页里看

**语音识别（参考 Handy 的做法）**
- 引擎：whisper.cpp（Rust 用 whisper-rs），Mac 上用 GPU（Metal），完全离线。Handy 也是 Tauri + Rust、MIT 许可，代码可以参考
- 模型：Whisper large-v3-turbo 量化版，约 550 MB，中日英韩都能认。第一次用点「安装语音模型」，有进度、能取消，核对 SHA-256，放 `tools/models/`（和 Demucs 同样的做法）
- Silero VAD：判断有没有在说话，说完自动停，不用按键（以后手机、电视上更需要）
- 两种用法，做法相反：
  - **问老师**：不固定语言；把这首歌的歌词当提示（initial prompt）给识别器，中文里夹的日语 / 英语词按原文写出来，而不是写成谐音。识别结果发出去之前先显示，可以改
  - **检查念歌词**：固定成歌曲语言，**不给**歌词提示（否则它会「听到」正确答案，念错也查不出来）；识别结果和歌词都转成读音（日语转假名、中文转拼音、英语按单词）再逐字对比
- 识别器听唱歌比听说话差很多，所以发音只在「念」这步查，「唱」这步看音高和节奏
- 现有的智能对齐用 macOS 自带识别（banzou-helper），先不动；Whisper 稳定后再看要不要换
- 风险：中文夹日语、日语夹中文到底能认多准，要用我的声音实测；太差就换专门处理混说的模型

**老师开口说话**
- 点评和回答都念出来，同时显示文字；可以关掉、调语速，正在练的句子播放时自动停
- 主用豆包语音合成（火山引擎，Doubao-Seed-TTS 2.0），声音自然、中文好；用户在火山引擎开通语音合成，把 API Key 贴进设置（旧版控制台的 APP ID + Access Token 也认），存在配置目录的 tts.json（只有本人可读）；设置里能挑音色
- 这是唯一一处把文字发到 Anthropic 以外的地方：只发老师要说的话，不发录音；合成好的声音按句缓存，同一句不重复花钱
- 备用：没配豆包或断网时用 macOS 自带语音（离线、免费），中日英韩都有
- 混说：老师的话是我的语言，里面夹着歌曲语言的词。让 Claude 把外语词标出来（如 `<ja>なつみ</ja>`）：先实测豆包能不能直接把中日混说念对；念不对就按段换音色或语种念。用 macOS 语音时一定按段换声音
- 示范发音时优先放原唱：老师讲到某个字，直接放原唱人声里这个字的那一小段（智能对齐已经有每个字的时间），合成语音只用来讲解
- 一边生成一边念：第一句话出来就开口，不等整段写完
- 待查：豆包的计费单价、并发限制，开通后实测
- 网络：豆包服务器在国内，开着 VPN 时走隧道连不上（实测 Astrill 的 Smart Mode 和排除列表都不一定生效）。所以应用发豆包请求时直接从 Wi-Fi / 网线出去、不进 VPN 隧道（Claude 照常走系统路由）；直连不通再按系统路由试一次；都不通 8 秒内提示，不让人干等

**AI 调用**
- Claude API key：设置里自己贴，和标签功能共用配置目录的 ai.json（只有本人可读），不进仓库；界面只显示末四位。不用钥匙串：应用没有开发者证书签名，每次更新后钥匙串都会再要一次密码
- 从 Mac 直接调 Anthropic API（Rust 后端发，key 不经过网页端），中间没有别的服务器
- 模型：`claude-sonnet-5-5`。备课一次、点评用低 effort 短回复；系统提示和课程放在缓存前缀里省钱
- 费用估算：备课一首约 0.1 美元，点评一次不到 1 美分，认真学一首约一两块人民币；设置里显示本月用了多少
- 没 key 或断网：听、唱、音高对比照常能用；已经备好课的歌能看读音和意思；只是没有新备课和点评

**不同设备怎么学**
- **电脑（先做）**：完整工作台。左边句子列表和进度，中间当前句（原文 / 读音 / 意思 / 难点）和音高曲线，右边老师对话
- **手机（以后）**：Mac 提供一个网页，同一个 Wi-Fi 下打开；一屏一句、大按钮，以听和念为主；手机录的声音传回 Mac 识别
- **电视（以后）**：在现有的电视 KTV（波点）上加一行读音，遥控器换句；老师的点评在 Mac 上合成好声音传给电视播。电视只负责显示和播放，运算还在 Mac

- 混说识别的实测结果，决定换不换模型

## 5. 后台（管理功能）

### 5.1 素材文件夹
- 第一次打开时选择素材文件夹，之后可在设置里换
- 监听文件变化，新放入的文件自动入库

### 5.2 自动配对规则
从文件名提取「歌曲名」作为配对键：

| 文件名模式 | 识别为 |
|---|---|
| `<歌名> - 伴奏.<wav/mp3/flac/m4a>` | 伴奏 |
| `<歌名> - 人声.<ext>` | 引导人声 |
| `<歌名>.lrc` | 歌词 |
| 其余视频文件 | 按歌名模糊匹配为原曲参考 |
| 其余音频文件（没有伴奏/人声标记） | 按歌名模糊匹配为「外部录音」（如 `月光.m4a`）；匹配不上的进未归类 |

- 同一首歌伴奏有多个格式时，优先 wav，其次 flac，其次 mp3
- 原曲 mp4 命名不统一（带 emoji、括号、「原唱：xx」），做模糊匹配给出建议，最终由我确认
- 从「（原唱：张三）」这样的片段自动提取原唱名
- 视频还按「歌名里的每个词都在文件名里」匹配（0.3.0）：繁体先转简体，中文词按子串找，英文词要整词出现，括号里的内容也算。例如「寂寞先生 曹格」配「曹格 Gary Chaw【寂寞先生】Official Music Video」，「几分之几 卢广仲」配「盧廣仲 Crowd Lu 【幾分之幾 You Complete Me】…」

### 5.3 歌曲信息编辑
歌名、原唱、版本、调、BPM、标签、备注；手动换绑某个音轨文件。

**已做（资料表，2026-11-13）**：每首歌旁边一个 `<歌名>.song.json`，规则和字段见 `docs/资料清单.md` §6。
- 稳定编号：建表时等于以前按歌名算的编号，之后改名也不变；标签、歌单、常点、电视预览都按它对。
- 演唱页「资料」：歌名（显示名，改了不动文件）、读音、歌手、语种、年代、背景、原曲名；「更多」里有演唱者、作词、作曲、版本。每项显示是谁填的（你 / AI / 扫描），你填的 AI 不会覆盖。
- 「改文件名」：先预览要改哪些文件（伴奏、人声、歌词、资料表、笔记、录音文件夹，必要时视频），确认后一起改，编号不变；中途失败全部改回。
- 顶部「资料」= 资料检查：按字段登记表列出每首歌缺什么、缺了哪些功能用不了（电视要伴奏 + 小 MV + 带时间的歌词；学唱要歌词 + 人声 + 语种；直播要伴奏 + 带时间的歌词），每个缺口有补法按钮（填写、AI 查、AI 搜歌词、打轴、智能对齐、做成伴奏、下载视频、同步电视）；还没有资料表的歌可以「预览建表 → 确认建表」，只新建文件，不改不删。
- 「AI 打标签」改名为补资料的一部分：结果写进资料表，同时补背景和原曲名，没歌词的顺手去 LRCLIB 搜。
- 还没做：调、BPM、手动换绑音轨。

### 5.4 设置
音频输出设备、歌词字号与主题（深色/浅色）、默认引导人声音量、快捷键。
学唱（4.12）：我的语言、Claude API key、豆包语音 APP ID / Access Token（存本机配置目录，只有本人可读）、老师音色和语速、本月 AI 用量、语音模型状态。

**网络路线**：应用要连的外部服务列成一张表，每个服务一行：名字、用在哪、走哪条路。
- 两条路：**直连**（从 Wi-Fi / 网线直接出去，不进 VPN 隧道，给国内服务用）、**跟系统走**（开着 VPN 就走 VPN，给国外服务用）
- 现在只有豆包语音是直连；Claude、YouTube、GitHub、LRCLIB、PyPI、Google 下载都跟系统走。以后加国内服务，在表里加一行
- 直连不通会再按系统路由试一次；每次请求都按表走，不靠 VPN 自己的「国内直连」（实测 Astrill 的 Smart Mode 和排除列表不一定生效）
- 设置里一页「网络」：每个服务显示路线，能改（直连 / 跟系统走 / 恢复默认），每行「测一下」，显示通没通、几秒；「全部测一下」一次测完
- 改过的路线存在配置目录 `network.json`；只记改过的，没改的跟着默认表走

## 6. 前端（技术方案）

| 项 | 选型 | 理由 |
|---|---|---|
| 桌面框架 | **Tauri 2** | 比 Electron 轻很多（安装包几 MB、内存小），Mac 上体验好 |
| UI | React + TypeScript + Vite | 生态成熟 |
| 状态管理 | Zustand | 简单够用 |
| 音频引擎 | Web Audio API | 两轨用同一个 AudioContext、同一起始时刻启动，保证伴奏与人声零漂移；GainNode 控音量 |
| 升降调（P1） | SoundTouch / Rubber Band 的 WASM 版本，跑在 AudioWorklet 里 | 实时变调不变速 |
| 歌词渲染 | requestAnimationFrame 读 `currentTime`，减去当前输出设备的延迟后二分查找当前行 | AirPods 会让声音晚 0.15–0.25 秒到耳朵，不补偿的话歌词会提前亮；同步误差 < 50ms |
| 音高曲线 / 波形 | Canvas 2D 自绘 | 数据量大，DOM 画不动 |
| 效果预览 | Web Audio 节点（BiquadFilter、DynamicsCompressor、Convolver） | 实时调参实时听；导出用 OfflineAudioContext 渲染 |

注意：一首 4 分钟立体声 wav 解码后约 85MB 内存，两轨约 170MB，可接受；切歌时释放上一首。

## 7. 后端（技术方案）

后端即 Tauri 的 Rust 进程，负责所有文件和数据操作，前端通过 IPC 调用。

### 7.1 职责
- 扫描目录、监听文件变化（`notify` crate）
- 文件名解析与配对
- SQLite 存曲库索引与元数据（`rusqlite`）
- 读写 LRC 文件
- 保存录音（P1）
- 调用 ffmpeg 从 mp4 抽音频（P2）

### 7.2 数据模型

```
Song      { id, title, artist, version, key, bpm, tags[], note, lyrics_offset_ms, created_at }
Track     { id, song_id, kind: accompaniment | vocal | original | recording | external, path, format, duration_ms }
Lyrics    { song_id, lrc_path }
Take      { id, song_id, name, path, starred, latency_ms, created_at, parent_take_id? }
PitchData { source_path, hop_ms, f0[], confidence[] }   // 音高检测结果缓存，原唱只算一次
TuneJob   { take_id, reference: vocal | scale, key, strength, speed, ranges[], output_path }
Note      { id, take_id, start_ms, end_ms, detected_cents,
            pitch_offset_cents, drift_correction, vibrato_scale, transition_ms, locked }
WorldCache{ take_id, f0_path, spectrum_path, aperiodicity_path }  // WORLD 分析结果缓存
Settings  { library_dirs[], output_device, font_size, theme, default_vocal_gain }
```

实现说明（M1）：歌词偏移直接写进 `.lrc` 的 `[offset:]` 标签；全局设置（耳机延迟、反应时间、音量）存为应用配置目录下的 `settings.json`。

实现说明（M2 起）：不引入 SQLite。每首歌的录音放在 `<素材文件夹>/录音/<歌名>/`，Take 信息（名字、标星、偏移、时间）存同目录 `takes.json`，修音编辑记录存 `take-01.tune.json`。和歌词一样，文件就是数据，删掉应用也不丢。

原则：**歌词以 `.lrc` 文件保存在歌曲旁边**（其他播放器也能用），数据库只存索引和元数据；删掉数据库重新扫描不丢东西（偏移量等元数据除外）。

### 7.4 录音与修音引擎

| 模块 | 方案 | 说明 |
|---|---|---|
| 录音 | Web Audio：`getUserMedia` 按设备 ID 打开 MacBook 麦克风（关闭回声消除 / 降噪 / 自动增益）+ AudioWorklet 采样，48kHz 单声道 wav | 和伴奏播放在**同一个 AudioContext 时钟**上，录音第一帧对应的播放位置可以精确算出，比另起一个 Rust 录音流再对时更准；每秒把数据交给后端追加写盘，崩溃不丢。WebView 拿不到麦克风时退回 Rust `cpal` |
| 麦克风权限 | Info.plist 写 `NSMicrophoneUsageDescription` | 首次录音系统会弹授权；被拒绝时引导去系统设置打开 |
| 耳机检测 | CoreAudio 读输出设备的连接类型（内置 / 有线 / 蓝牙），监听设备切换 | 中途换耳机、AirPods 自动切换到 iPhone 断开时，暂停录音并提示 |
| 指定麦克风 | 录音按设备 ID 打开 MacBook 内置麦克风，不用系统默认输入 | 避免 AirPods 连上后系统自动把默认输入切成 AirPods，导致蓝牙进入通话模式 |
| 自动对齐 | 录音和原唱人声各算起音强度曲线，在 ±150ms 范围内做互相关，找出最佳偏移 | 兜底蓝牙延迟每次连接都略有不同；没有原唱人声的歌退回只用校准值 |
| 延迟补偿 | 跟拍校准测出的延迟按输出设备保存；录完把录音整体前移 | 有线耳机对齐误差 < 10ms；蓝牙 < 20ms（蓝牙延迟本身会小幅波动） |
| 降噪 | 用录前 2 秒底噪做参考 + `nnnoiseless` | 自带麦克风底噪明显，降噪是必需项而不是可选项 |
| 音高检测 | pYIN 算法（Rust 实现） | 人声音高检测的成熟方案；原唱 `人声.wav` 结果缓存 |
| 修音合成 | TD-PSOLA（纯 Rust 实现） | 按音高周期切片重叠相加，只改音高、保留共振峰（音色），半音以内的修正很自然；纯 Rust 无需编译 C 库。效果不够时再换 WORLD |
| 处理方式 | 离线处理 + 进度条，先处理当前选区方便快速试听 | 4 分钟人声全曲修音预计十几秒到几十秒 |

### 7.5 手动修音引擎

| 环节 | 方案 |
|---|---|
| 音符切分 | pYIN 音高 + 有声/无声判断 + 起音检测（频谱通量）切出音符；原唱的音符边界作为辅助参考 |
| 编辑模型 | 每个音符只存参数（音高偏移、拉直、颤音比例、过渡时长），目标音高曲线 = 原始曲线按参数计算得出；自动修音和手动修音共用这一套参数 |
| 即时试听 | WORLD 分析结果（音高 / 频谱 / 气声）按 Take 缓存到磁盘，修改时只重新**合成**受影响的那个音符（前后各留一点过渡），交叉淡化拼回去；目标：松手到听到 < 300ms |
| 存储 | 编辑记录存为 `take-01.tune.json`，放在录音旁边；原始 wav 不改 |
| 撤销 / 重做 | 前端维护编辑历史（命令模式），每步只记录参数变化 |

**风险**：手动修音是整个项目里工作量最大、最难调到好用的部分（切分准确度、合成音质、交互手感）。所以先做自动修音（M3），共用的底层（音高检测、WORLD 合成、参数模型）在 M3 打好，M4 再做手动编辑界面。

## 1. 约定

**一首歌 = 一个「歌名键」**：伴奏 / 人声文件名去掉「 - 伴奏」「 - 人声」后的部分（`library.rs` 的 `Song.title`，`normalize_title` 后是 `Song.id`）。歌词 `.lrc`、原曲视频、外部录音都靠它配对。没有伴奏也没有人声的歌不会出现在曲库里（只有歌词的 `.lrc` 会掉进曲库栏底的「待处理」）。

**歌曲编号（`songId`）**：稳定编号，存在资料表 `<歌名键>.song.json` 的 `id` 里，建表后永远不变（改文件名也不变）。建表时取「歌名键去首尾空白后 SHA-256 的前 6 字节」（12 位十六进制，`tv.rs` `song_id`），所以和以前的编号一样；还没有资料表的歌，编号就是这个算出来的值。扫描结果里带着它（`Song.songId`），前端不要自己按歌名算。`tags.json` 的歌单、常点、电视上的预览文件名和点歌请求都用它。

**显示名**：资料表的 `title`；空着就是歌名键。改显示名不动任何文件。

**谁来填**

| 记号 | 意思 |
|---|---|
| 扫描 | 应用扫描文件夹自动得到 |
| 用户 | 用户亲手填 / 亲手放文件 |
| AI | Claude 猜或联网查（可能错，用户改过的不能被覆盖） |
| 工具 | 应用里的功能生成（下载视频、做成伴奏、录音、打轴、转换等） |
| 派生 | 由别的资料算出来，不单独存（或只存缓存） |

**状态**：✅ 已有 · 🟡 有但不完整 / 有毛病 · 📝 计划中（文档提到、代码没有）

## 2. 资料放在哪

| 位置 | 内容 | 删了会怎样 |
|---|---|---|
| 素材文件夹（第一层） | 伴奏 / 人声 / `.lrc` / 原曲视频 / 外部录音 / `歌名 - 原曲.m4a`；计划：`歌名.notes.md`、`歌名.lesson.json`、`歌名.song.json` | 文件本体，丢了就是丢了 |
| 素材文件夹 `录音/<歌名>/` | 每遍录音、`takes.json`、修音记录、拼接和修音结果、导出、老师对话 | 同上 |
| 素材文件夹 `录音/升降调缓存/` | 升降调后的伴奏 / 人声 | 缓存，会重算 |
| 配置目录（`~/Library/Application Support/<应用>/`） | `settings.json`、`library.json`、`tags.json`、`plays.json`、`tv.json`、`practice.json`、`teacher-notes.md`、`tts-cache/`（老师念过的话的声音缓存，按音色 + 文字存，删了会重新合成）、`network.json`（设置 →「网络」里改过的服务路线，不是歌曲资料），以及两个存密钥的文件（`ai.json`、`tts.json`，不是歌曲资料，本文不读不写） | 应用设置和标签会丢 |
| 缓存目录（`~/Library/Caches/<应用>/`） | `pitch/` 音高、`transcripts/` 语音识别、`tv/previews/` 电视预览和 `catalog.json`、`video/`、任务状态 | 缓存，会重算 |
| 电视（`/sdcard/BanzouKTV/`） | `.catalog/`（歌单 + 预览 + 常点）、`<歌名>/`（整首）、`.requests/` | 重新同步 |

原则（PRD 7.2）：**文件就是数据**，删掉应用也不丢；缓存可以随时删。

## 5. 已发现的问题（通用）

1. ✅（已解决：稳定编号 + 显示名，见 §6）**歌名既是显示名又是身份键。** 编号、`录音/<歌名>/` 文件夹、`.lrc`、`.notes.md`、`transposeBySong`、电视上的文件夹名全从歌名来。改一次歌名 = 编号变了 → 标签、歌单、常点、电视预览全部对不上；录音文件夹、歌词、笔记也要一起改名。这是现在最大的结构问题，也是「改歌名」一直没敢做的原因。
2. ✅（已解决：都并进资料表，`by` 记来源）**歌手有两处来源**（扫描 vs 标签），优先级只在界面和电视同步两处各写了一遍，没有统一出口；扫描只在视频名带「原唱：」时才有，覆盖很少。
3. ✅（已修：前端认 `track`；后端只清空「手动改过」的字段）**标签字段前后端不一致**：后端写 `note`、`track`，前端 `normalizeStore` 只认 `note`，保存时会把 `track` 丢掉；「手动改过」只覆盖 artist / lang / era。

9. ✅（已做，2026-11-13）**异常录音没人管。** 录音崩溃恢复只会把 `.wav.part` 原样「恢复」成一遍，不看长短（实际出现过：一个按 48 kHz 单声道算约 3.5 小时、2.4 GB 的未完成录音，多半是忘了停）。应用从不自动删录音，所以它一直躺着。规则：①录音超过 歌长 + 30 秒自动停并提示；②恢复时 `.part` 长度超过歌长 1.5 倍且至少多出 60 秒（或没有歌长时超过 15 分钟），不自动恢复成一遍，标成「异常录音」列进资料检查页；③只做「一键移到废纸篓」（能找回），不静默删除，录音是创作、不能重来。
   - 怎么做的：①`useRecording.ts` 等停止时按墙上时间算，超过 `player.duration + 30 秒`（`recordGuard.ts` 的 `AUTO_STOP_EXTRA_SECONDS`）照常停、照常保存，提示「录音比歌长了 30 秒，已自动停止」。②歌长由后端读这首歌 wav 伴奏（没有就 wav 人声）的文件头（`recording::song_seconds`）；只有 mp3 / m4a 时按「不知道歌长」算。`.part` 长度 =（字节 − 44）÷ 4 ÷ 采样率。超长的不补头、不改内容，只改名成 `take-NN.异常录音.part`（不再被恢复、不进录音列表、新录音不占这个编号，反复打开也不会再动它）。③资料检查页顶部列出「异常录音」：歌名、文件名、大小、大概多长、「移到废纸篓」（走 `trash_takes`，移进 `~/.Trash`）；资料检查扫描时也会把很久没写（> 1 分钟）的超长 `.part` 标成异常，正在录的不动。打开这首歌时录音列表下面也提示一句。
10. **歌手 ≠ 演唱者。** 一首歌的创作者和演唱者可以是不同的名字（AI 歌曲、虚拟歌手、翻唱），现在只有一个 `artist`，歌名和视频文件名常常写的是演唱者。规则：`artist` = 用户选定的显示歌手（一般是创作者），演唱者另存为附注。
11. ✅（资料检查页）**缺什么没人知道**：没有任何一处能回答「哪首歌缺什么」，每个新功能都是用到才发现缺。

## 6. 统一资料表（已实现，2026-11-13）

### 6.1 方案

每首歌一个 **`<歌名键>.song.json`**，放在歌旁边（和 `.lrc`、`.notes.md` 一样，文件就是数据）；再加一份**字段登记表**，每个字段登记「谁来填、哪些功能要用、缺了怎么补」，新功能只需要登记字段。

```json
{
  "schema": 1,
  "id": "0123456789ab",          // 稳定编号，创建时算一次，之后永远不变（改名也不变）
  "key": "<歌名键>",              // 当前对应的文件名键，仅用于对账
  "title": "…",                   // 显示名，可以随便改
  "titleReading": "…",            // 读音
  "artist": "…", "performer": "…",       // artist = 显示歌手（创作者）；performer = 演唱者（可选）
  "lyricist": "…", "composer": "…",
  "lang": "国语", "era": "10s", "version": "…",
  "source": { "url": "…", "videoTitle": "…", "channel": "…" },
  "note": "…", "track": "…",
  "by": { "artist": "user", "lang": "ai", "era": "ai" }   // 每个字段谁填的；user = 锁定，AI 不覆盖
}
```

- **稳定编号**：已有的歌，编号就取现在的 `songId(歌名键)` 并写进文件——所以标签、歌单、常点、电视预览**一个都不用重编**。以后改显示名只改 `title`，编号不变。
- **改文件名**：单独一个「重命名」操作，一次性把伴奏、人声、歌词、视频（可选）、笔记、`录音/<歌名>/`、`.song.json` 一起改并更新 `key`，编号不变；电视用编号找歌，不再靠文件夹名。
- **`by` 取代 `manual`**：`by.<字段> == "user"` 等于现在的「手动改过」，而且所有字段都适用。

实现：`src-tauri/src/songmeta.rs`（读写、合并旧标签、改文件名、建表、资料检查、AI 补齐），命令都走 `song_meta(cmd, args)` 一个入口（测试桥同一个）：`tags_load`、`tags_save`、`song_view`、`song_meta_save`、`song_rename_plan`、`song_rename`、`songs_migrate_plan`、`songs_migrate`、`songs_check`。界面：`src/songs/SongInfoDialog.tsx`（「⋯」→「歌曲资料…」）、`src/songs/CheckDialog.tsx`（「待处理」→「资料检查与补齐…」）。

- 资料表的字段是开放的：后端只管 `schema / id / key / by` 和语种、年代的取值，其他字段原样存。读不懂的资料表不会被覆盖，资料检查里报出来。
- 没有资料表的歌：从 `tags.json` 的旧标签 + 扫描结果拼一份来显示，不写盘；第一次改这首歌的资料（或建表）时一起写进资料表。
- 改文件名会改：伴奏、人声、歌词、`.song.json`、`.notes.md`、`.lesson.json`、`录音/<歌名>/`；视频和外部录音按名字挂歌，改完还挂得上就不动，挂不上就在文件名前面加「新歌名 - 」。先预览，确认才改；中途失败全部改回去。升降调记录（`transposeBySong`）跟着换键。
- 电视：歌单里 `id` = 稳定编号、`title` = 显示名，点歌首字母优先按读音里的罗马音算；传整首时 `info.json` 多写 `id`、`name`；电视点歌请求先按编号（`<编号>.req`）找歌。电视端（APP 版本 6）按 `info.json` 的 `id` 认歌（没有 `id` 的老传输按 `title` 算，和以前一样），歌名以同步过去的歌单为准。

### 6.2 字段登记表（`src/songs/fields.ts`）

每个字段一条：

```
{ key, label, where: sheet|file|tv, input?, filledBy: [user|ai|scan|tool], required: [功能…], helps: [功能…], fix: [补法…], neededWhen?, has?, optional?, missing? }
```

功能：唱歌、录音修音、直播、电视 KTV、学唱、标签歌单。补法：填写、AI 查、AI 搜歌词、打轴、智能对齐、做成伴奏、下载视频、同步电视。

| 资料 | 缺了用不了 | 缺了差一点 | 补法 |
|---|---|---|---|
| 读音（只有日语 / 韩语歌才算缺） | — | 电视、学唱 | 填写 |
| 歌手 | — | 电视、标签、学唱 | AI 查、填写 |
| 语种 | 学唱 | 电视、标签 | AI 查、填写 |
| 年代 | — | 电视、标签 | AI 查、填写 |
| 背景 | — | 学唱、标签 | AI 查、填写 |
| 原曲名 | — | 标签（搜歌词用） | AI 查、填写 |
| 伴奏 | 唱歌、录音、直播、电视 | — | 做成伴奏、下载视频 |
| 人声 | 学唱 | 唱歌、录音、电视 | 做成伴奏、下载视频 |
| 歌词 | 电视、学唱、直播 | 唱歌、录音 | AI 搜歌词、打轴 |
| 歌词时间轴（有歌词时） | 电视、直播 | 唱歌、学唱 | 智能对齐、打轴 |
| 原曲视频 | — | 电视 | 下载视频 |
| 电视小 MV（20 秒副歌预览带画面） | 电视 | — | 同步电视（只有声音时先下载视频） |
| 电视歌单是最新的 | — | 电视 | 同步电视 |

可选（能填、不算缺）：歌名（显示名）、演唱者、作词、作曲、版本。用户特意清空的字段（`by` 是 user、没有值）也不算缺。

- 「资料检查」= 登记表 × 每首歌的 `.song.json` × 扫描结果，算出每首歌缺什么、缺的是不是某个功能的必需项。
- 新功能要加字段：先在这里（和 §3）登记，再加登记表一行，检查页自动多一列。
- 不放进 `.song.json` 的：文件是否存在（扫描）、MV 选哪个（派生）、录音和修音（`录音/<歌名>/`，继续用自己的文件）、缓存。

### 6.3 已有资料怎么并进来（不重复）

| 现有 | 并入方式 |
|---|---|
| `tags.json` 的 `songs[编号]`（artist / lang / era / note / track / manual） | 资料检查里「预览建表 → 确认建表」一次建好（或改某首歌时顺带建）；`manual` 转成 `by: "user"`，其余标 `ai`。之后 `tags.json` 的 `songs` 不再写，原样留着当备份；标签窗口读写走 `tags_load` / `tags_save` |

| `transposeBySong` | 暂时还在设置里按歌名键记；改文件名时跟着换键。以后再迁进资料表 |
| `.notes.md` 里的 `读音：` | 老师纠正读音是一条通道，写入时**同时**更新 `titleReading`，笔记和资料表不会各说各话（✅ 已接：`learn/teacher.rs` 的 `sync_title_reading`，撤销时一起换回） |

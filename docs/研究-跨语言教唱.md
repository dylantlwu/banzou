# 研究：跨语言教唱，现在有哪些系统和模型可以用

> 给波点「外语学唱」（PRD §4.12）找方向。查询日期：**2026-11-13**（下文所有链接都是这天访问的）。
> 写法：每个面先写结论，再附比较表。查不到原始依据的标「未查证」；只看到摘要或第三方转述的标「二手」；根据资料推出来、还没实测的标「推断」。
> 只做研究，没改代码，也没改 PRD。最后一节「对波点的建议」列出 PRD 要改的地方。

## 0. 一页结论

1. **读音不能只靠 Claude，也不能只靠词典。** 常用汉字的读音已经基本解决：本机分析器约 96–97% 对，前沿 LLM 99.4–99.9%。但**歌名、人名、当て字**没有任何公开的准确率数字，词典里也常常没有这个读法：「夏実」在专有名词词典 JMnedict 里只有なつみ，只有歌词站 utaten 写着「よみ：かじつ」。这类读音只能来自歌曲自带的标注或用户确认。波点现在「笔记优先、待确认」的规则是对的，还缺**本机读音流水线**和**每个读音带来源**。
2. **听用户说话：只用 Whisper 不够稳。** 中英混说时 Whisper 明显落后 SenseVoice 和 Qwen 系（CS-Dialogue 上错误率 15.3% 对 6.7%），还会把混说句子翻译成一种语言。中文夹日语没有公开评测。2026 年开源的 **Qwen3-ASR**（Apache-2.0）值得和 Whisper-turbo 一起实测。Handy 现在的底层已经换成 **transcribe.cpp**（MIT，Metal，有 Rust 绑定），一套代码能跑 Whisper、Qwen3-ASR 和 SenseVoice。
3. **查念得对不对：光比对 ASR 文字有盲区。** 带语言模型的识别器会把念错的音「纠正」成正确的词。要加第二路：用直接输出假名或音素的模型，拿歌词读音做强制对齐，给每个音拍打分（GOP 思路）。云端的发音评测里，日韩中三种都覆盖的只有 Azure 和 SpeechSuper，日韩都没有音素级，而且要上传录音，和 PRD「录音不离开电脑」冲突。
4. **唱歌不评发音。** 清唱时 Qwen3-ASR 的错误率 3–8.5%，Whisper 9.5–13.8%；带伴奏时 Whisper 是 32–35%。唱歌的发音打分没有可用的产品，PRD「唱这步只看音高和节奏」是对的。
5. **对齐：本机首选 Qwen3-ForcedAligner-0.6B。** 支持日韩中等 11 种语言，平均偏差 43 ms（WhisperX 133 ms），Apache-2.0。MFA 最准，但难以打包进 Tauri。
6. **老师开口：豆包可以继续当主力，但日语要直接送假名。** 豆包 2.0 不支持 SSML，没有日语读音标签；有日语 2.0 音色（Hana、Bonnie 标注了「教学场景」）。3 元/万字符，默认 10 并发。官方写明能用假名指定日语读音的只有 Azure、MiniMax 和本地的 IndexTTS-2.5。最稳的做法是让老师输出「原文{读音}」，送去合成时只送读音。
7. **教学互动：** 值得学的是短循环、先慢后快、自己和原唱并排回放、先回想再给答案、间隔复现、只纠一处、课后小结。要避开的是用说话的标准评唱歌、红色加百分比、ASR 误判还硬判、字太多、排行榜金币。现成产品（Apple Music Sing、Spotify 翻译、LyricsTraining）**都只做到看懂，没有「听你念、听你唱、再纠正」**，这正是波点的空位。
8. **LLM 当老师：先查证再说。** 公开评测里，Claude Sonnet 4.5 在「多读音汉字选哪个」的题上只有 0.773，商用模型里最低。音高重音和中文多音字都没有 LLM 的评测数据。所以读音由本机工具给，Claude 只做仲裁和讲解，讲到没确认的读音就说「待确认」。价格已在官方页核实：Sonnet 5.5 每百万 token 输入 $2、输出 $10，缓存读 $0.10。

## 1. 读音来源：从歌词到读音

### 1.1 结论

- **日语常用汉字**已经基本解决。在 Joyo-Kanji-Yomi 基准上：MeCab+UniDic 96.66%、OpenJTalk 96.63%、Sudachi 97.32%，GPT-5.6 99.85%、Gemini 3.1 Pro 99.78% [R1]。另一项研究在 3000 句人工标注的日语句子上测了 30 多个 LLM：最好的 LLM 假名错误率（CER）在 0.52% 以下，最好的传统工具 1.03%；先让 LLM 分词、再按规则转假名（parse 模式），普遍比让它直接写读音准 [R2]。
- **歌名、人名、当て字没有任何公开数据。** 作词人自己定的读音只能从官方或歌词站的注音得到。「夏実」：JMnedict 里只有なつみ [R5]，utaten 歌词页写着「よみ：かじつ」[R16]，英文歌词站标题写「夏実 (Kajitsu)」[R17]。
- **Rust 本机可以做全套日语读音，不需要 Python**：Lindera（MIT）或 vibrato（MIT/Apache）分词出读音；sudachi.rs（Apache-2.0，能标出未知词）交叉比对；jpreprocess（BSD-3，OpenJTalk 前端的 Rust 版）补音高重音；wana_kana（MIT）做假名和罗马字互转。
- **中文拼音**：pypinyin 和 Rust 的 `pinyin` crate（都是 MIT）多音字会错。g2pW 在 CPP 数据集上 99.08% [R7]，罕见读音可能只有 58.8–83.3%（二手）[R8]。`pinyin` crate 有没有做短语级多音字消歧：未查证。
- **韩语**：唱歌要的是**发音形式**（연음、경음화、비음화），按字转写的罗马字给不出来。g2pK（Apache-2.0）能给发音形式，但它是 Python、依赖 mecab-ko，2022 年后没有更新 [R9]。没找到 Rust 实现：未查证。
- **英语**：CMUdict 查词，词典外的词用 g2p_en（Apache-2.0）。英语按 PRD 只给难词标音，够用。
- **授权雷区（波点是 MIT 开源）**：espeak-ng、phonemizer、pykakasi、Rust 的 kakasi crate、korean-romanizer 都是 **GPL-3**，不要链接也不要打包。UniDic 是 GPL/LGPL/BSD 三选一，选 BSD。新词词典 NEologd 2020-09 起停更，收不到新歌名。
- **怎么判断一个读音靠不靠得住**（按优先级）：
  1. 用户确认过的（老师笔记、资料表的歌名读音）；
  2. 歌曲自带的标注：官方歌词本或 MV 的注音、歌词站的ふりがな、YouTube 标题里的罗马字；
  3. 几个本机分析器结果一致，不是未知词，也不是专有名词；
  4. 专有名词词典里只有一个候选；
  5. LLM 给的。

  第 3 步不一致、出现未知词（MeCab n-best 前两名读音不同，Sudachi 标 `(OOV)`）、词性是固有名詞，就标「待确认」。还可以用分离出的原唱人声跑输出平假名的识别器，在两个候选里二选一。这只是思路，**没有公开准确率**（未查证），只能当旁证。

## 2. 听用户唱或念：识别和发音评分

### 2.1 结论

- **单一语言精度**（FLEURS，同一框架 transcribe.cpp Q8_0，字错率 %）：

  | 模型 | 日 | 中 | 韩 |
  |---|---|---|---|
  | Whisper large-v3-turbo | 4.82 | 8.50 | 5.24 |
  | Qwen3-ASR-1.7B | 5.29 | 7.14 | 4.60 |

  两者互有胜负。SenseVoice-Small 的日语错误率是最好模型的约 3.3 倍，不适合检查日语。
- **混说**：中英混说测试集 CS-Dialogue 上，错误率 Whisper large-v2 15.29%、Qwen2-Audio 9.76%、Paraformer 9.65%、SenseVoice-Small 6.71%；另一个测试集 ASCEND 上，Whisper large-v3 23.22%。论文还记录了 Whisper 会把混说的句子翻译成一种语言 [B-cs]。**中文夹日语没有任何公开评测**（未查证），只能用自己的声音录 20–50 条测。
- **Qwen3-ASR**（2026-01，0.6B / 1.7B，Apache-2.0）：支持 30 种语言加 22 种中文方言，自动判断语种准确率 97.9%，有 `context` 参数放热词，训练数据包含唱歌和带伴奏的整首歌。在 Mac 上 1.7B 5-bit 约 36 倍实时、内存 1.9 GB（第三方测试）。
- **Handy 现在的做法**：官方模型页列了 Whisper、Parakeet、Moonshine、SenseVoice、Cohere Transcribe、Breeze、Canary、GigaAM，底层是同一作者的 **transcribe.cpp**（MIT，Apple Silicon 上自动用 Metal，有官方 Rust 绑定，支持 Qwen3-ASR 和 SenseVoice，内置 Silero VAD）。这一点已在仓库页核实。
- **用歌词当提示有风险**：静音或听不清时，Whisper 类模型会把提示原样吐出来。所以要先过 VAD，提示只放几个关键词。Qwen3 的热词也有原样出现在输出里的报告（二手）。
- **念歌词检查**：PRD 已决定不给歌词提示，这是对的。但带语言模型的识别器仍会把念错的音「纠正」成常见词。要补一路**不靠词典的假名或音素识别**：
  - 口音和二语语音上，wav2vec2-xlsr-53-espeak-cv-ft（Apache-2.0）的音素特征错误率最好（12.89）；
  - 日语可以用直接输出平假名的 CTC 模型，拿歌词读音做强制对齐，给每个音拍打分。这些多是个人微调的模型，质量参差，授权要逐个看。
- **发音评分服务**：
  - Azure 覆盖 33 个 locale，含 ja-JP、ko-KR、zh-CN。但音素名只有英语和中文输出，韵律分只有英语，而且要上传录音。
  - SpeechSuper 支持日韩，但只到字和句级，音素级只有英语；每句 0.006 美元。
  - 腾讯、有道、讯飞的文档只写了中文和英文。
  - 开源 GOP（GOPT 等）都是在英语数据上做的，日韩要自己搭。
- **唱歌**：
  - 清唱干声：Qwen3-ASR-1.7B 错误率 3–8.5%，Whisper-large-v3 9.5–13.8%。
  - 带伴奏整首歌：Qwen3 约 14%，Whisper 在 Jam-ALT 上 32–35%；先用 Demucs 分离再识别反而更差（48%）。
  - 唱歌的发音打分只有原理验证和小研究，没有可用产品。

## 3. 对齐：歌词和人声逐字或逐音素对齐

### 3.1 结论

- **本机首选 Qwen3-ForcedAligner-0.6B**（Apache-2.0）。支持 11 种语言（含中日韩，已在论文摘要核实），输出字或词级时间。平均偏差：日 42.4 ms、韩 37.2 ms、中 33.1 ms，平均 42.9 ms；WhisperX 133 ms，NeMo NFA 130 ms。拼成 300 秒长音频时仍有 52.9 ms，WhisperX 是 2708 ms。单段最长 5 分钟，权重约 1.8 GB（二手），有第三方 ONNX 和 MLX 版。在歌声上的表现：未查证。
- **最准的是 MFA 3.0**：日语音素边界平均 10.8 ms，韩语 14.8 ms。但依赖 Kaldi 和 conda，难以打包进 Tauri。适合开发时做标注和精度基准。
- **备选**：wav2vec2 字符或假名 CTC 加自己写的 Viterbi，用 ort 跑。WhisperX 就是这样做的，词级偏差约 110 ms。
- **唱歌对齐**：
  - 带伴奏的整首歌，学术最好水平平均误差约 0.2 秒；人声分离的质量影响很大。
  - 社区工具 SOFA（MIT）和 HubertFA（Apache-2.0，有中日英粤 ONNX）为 DiffSinger 和 OpenUtau 做音素标注，针对清唱干声。
  - 开源卡拉 OK 项目 Nightingale 的做法：先查现成 LRC（LRCLIB），没有再「分离人声 → WhisperX → 日中按字对齐」；Qwen3-ForcedAligner 是它的实验选项。
- **对波点**：用户在「念」和「唱」时的录音本身就是干声，直接用语音对齐器。原唱用分离出的人声加已打好轴的 LRC，按句切段再对齐。现有智能对齐（macOS SpeechAnalyzer 逐字比对）可以先不动。
- **授权雷区**：MMS 系对齐权重（ctc-forced-aligner 的默认模型、torchaudio MMS_FA）是 **CC-BY-NC，不能商用**；whisper-timestamped 和 aeneas 是 **AGPL**；torchaudio 2.9 已删除 forced_align。

## 4. 老师开口：多语种语音合成

### 4.1 结论

- **豆包语音合成 2.0 可以继续当主力**（以下已在火山引擎官方文档核实）：
  - 价格：按量 3 元/万字符；资源包 2.8 到 2.1 元/万字符；默认 10 并发，加购 100 元/并发/月。PRD 里「待查：计费单价、并发」可以填上了。
  - 日语：有日语 2.0 音色，Hana、Bonnie 标注了「教学场景」；Vivi 2.0 写明支持中文和日文；部分音色能用 `enable_language_detector` 或 `explicit_language` 指定语种。
  - 其他能力：`enable_subtitle` 能返回字级时间；`cache_config` 让服务器缓存相同文本 1 小时。
  - **2.0 音色不支持 SSML**。即使是 1.0 的 SSML，`<phoneme>` 也只支持中文拼音和英文音标，**没有日语**。所以要让「夏実」念成かじつ，只能**把送去合成的文字直接写成假名**。波点现在就是这样做的：按笔记替换，有假名就整句标 `explicit_language=ja`。
- **现有做法的漏洞**（推断）：日语里不带假名的汉字词（如「花火」「心」）会留在中文那部分，被按中文念。老师的话只要提到这类词，就会念错。
- **官方写明能用假名指定日语读音的只有三家**：
  - Azure：ja-JP 的 `sapi` 音素集就是片假名，另有 PLS 自定义词典；
  - MiniMax：`pronunciation_dict`，官方示例 `東京/トウキョウ`；
  - IndexTTS-2.5（本地开源）：`<上手|じょうず>`，许可有商用条件，在 Mac 上能不能跑未查证。
- **一句话里中日夹杂，没有哪家保证质量。** 只有 Azure 的 multilingual 音色写明可以用 `<lang>` 在词级切换。
- **OpenAI 的 `tts-1` 和 `gpt-4o-mini-tts` 已废弃**，2027-01-06 停服，不要接。
- **Mac 本机兜底**：系统语音免费、离线，可以用 IPA 属性，但 ja-JP 音色是否遵守 IPA 未查证。开源模型里，Kokoro 的日语音色官方自评 C 级、中文 D 级；F5-TTS 权重不可商用；Chatterbox 已归档；VibeVoice TTS 已被下架。都不适合当主力。
- **示范唱不用合成**：继续放分离出的原唱人声，PRD 已经这样写。

## 5. 现成的教学产品怎么设计互动

### 5.1 结论

- **最值得学的是三件事：短循环、有示范可对照、每次只纠一处。**
  - ELSA 的流程是「听示范 → 录音 → 分解反馈 → 再来」；
  - Pimsleur 是「先让你想、再给答案」，再按递增间隔复现；
  - B 站给中文用户教日语歌的常见结构：选几十秒的片段，汉字全换成假名并标罗马音，每段配慢放跟唱，单独讲易混的音（如 づ 和 zu），最后给带汉字的版本。

  这些和波点的「听 → 念 → 唱 → 一句点评」完全对得上。
- **有研究支持**：
  - Ludke 等人 2014 年让 60 名成人学 15 分钟匈牙利语，唱的组优于说的组和有节奏地说的组，优势在逐字记忆。
  - ASR 发音训练的元分析（Ngo & Chen 2024，15 项研究）：总体效应 g=0.69；显式纠正效果大；对单个音效果大，对重音、语调效果小。
  - Neri 等人指出 ASR 偶尔判错会损害学习，所以**判不准时宁可不判**。
- **K 歌类**：实时音高线是标配。抱怨集中在延迟和误判，打分算法都是黑盒。全民K歌有没有外语逐句教唱：未查证。
- **学外语歌的现成工具都只做到看懂**：
  - Apple Music Sing（iOS 26）有逐行翻译和读音，但只在 iPhone/iPad 上有，Mac 上没有；
  - Spotify 歌词翻译 2026-02 全球上线，没有罗马音；
  - LyricsTraining 只练听写填空。

  没有一个产品会「听你念、听你唱、再纠正」。

### 5.3 值得学的、要避开的

**值得学**
- 一句一循环，一个循环 1–2 分钟（推断）。
- 先慢放、后原速。固定两档：0.75 倍和原速。
- 注音分层：先给假名加罗马音，熟了换成汉字加ふりがな，最后只留原文（B 站教唱的进阶方式）。
- 「你念的 / 原唱」两个按钮并排回放（ELSA），比任何分数都直观。
- 先回想、再给答案（Pimsleur）：复习时先只放伴奏，让学的人自己接这一句，再放原唱核对。
- 间隔复现：学过的句子穿插在后面的句子之间回来。
- 只纠一处，挑最影响听懂的那个（CAPT 系统综述）。
- 课后一张很短的小结：今天修好了哪几处，下次先练哪句（Praktika 正因为缺这个被批评）。

**要避开**
- 用说话的标准评唱歌。
- 红色加百分比：ELSA 式的红黄绿和总分容易让人沮丧。波点已经用橙色、不给总分，保持下去。
- ASR 没把握还硬判：低置信度时改说「再听一遍原唱这一句」，并留一个「我觉得我念对了」的按钮。
- 音高线有延迟：K 歌 App 的头号抱怨。波点已有延迟补偿。
- 字太多：老师一次讲解控制在约 15 秒（推断）。
- 排行榜和金币：对「学会一首自己喜欢的歌」帮助有限。

## 6. LLM 当老师：容易错在哪里，怎么压住

### 6.1 结论

- **有文献支持的错误类型**：
  - 多读音汉字按上下文选错，或选了不常见的读音（YOMI-Bench：Claude Sonnet 4.5 多读音判断 0.773）；
  - 生成读音时凭空加字或漏字；
  - 编造音乐事实（歌手、专辑、发行日期），有 MusicSimpleQA、TrustMus 等专门基准；
  - 讲错语法规则（Duolingo Max 用户报告的个例）。
- **没有数据的**：
  - 日语音高重音：没找到任何评测 LLM 的论文（未查证）。专用模型约 89.8–93.2%（二手）。
  - 中文多音字：没找到 LLM 和 g2pW 正面对比的数据；Phun-Bench（ACL 2026）的结论是 LLM 记得住读音但不会灵活运用。
  - 方言、歌名被翻译：没找到量化研究。

  这几件事都**不能交给 Claude 自己判断**。
- **Anthropic 官方建议的降幻觉方法**：允许说不知道；先摘原文再回答；要求引用；同一问题多跑几次比较；限定只用所给资料。
- **API 能直接用的**：
  - 结构化输出：`output_config.format`，或在工具定义上设 `strict: true`。只保证 JSON 格式合法，不保证内容对。
  - Citations：引用一定指向给它的文档，引用的原文不计输出 token。但**不能和结构化输出同时开**，会返回 400。
  - 提示缓存：Sonnet 5.5 缓存读取是 0.05 倍价格；每次请求最多 4 个断点。
- **竞品的做法**：
  - Duolingo：提示词调优加人工持续审核；对话分段，小步骤单独调用，通话后提取记忆。
  - Praktika：多个智能体分工（二手）。
  - Speak：防错机制没有公开。

  **没有一家公开过读音核对机制**。
- **价格**（官方价目页核实，每百万 token）：

  | 模型 | 输入 | 输出 | 缓存读 |
  |---|---|---|---|
  | Opus 5.5 | $4 | $20 | $0.20 |
  | Sonnet 5.5 | $2 | $10 | $0.10 |
  | Haiku 5.5 | $0.10 | $0.50 | $0.01 |

  Haiku 5.5 的价格是提示 ≤10 万 token 时的；超过后输入 $0.50、输出 $2.50。一次讲解按输入 5k、输出 1k token 算，Sonnet 约 $0.02；输入走缓存后更低。PRD「点评一次不到 1 美分」在短回复加缓存命中时成立（推断）。

### 6.2 比较表：防错方法

| 方法 | 怎么做 | 效果 | 本机 / API | 费用 | 来源 |

## 7. 对波点的建议

### 7.1 每个环节用哪个方案

| 环节 | 建议方案 | 为什么 |
|---|---|---|
| **读音来源** | 本机 Rust 读音流水线：Lindera（UniDic，选 BSD 许可）和 sudachi.rs 交叉比对，jpreprocess 补重音，wana_kana 转罗马字。中文先用 `pinyin` crate 并只标多音字；韩语发音形式先由 Claude 给并一律标「待核对」；英语用 CMUdict。来源优先级：老师笔记 / 资料表的歌名读音 > 歌曲自带标注 > 分析器一致 > 词典 > Claude | 都能在 Rust 里跑、授权干净。常用字靠分析器，专有名词靠标注和用户，Claude 只做仲裁，符合「读音待确认、不按常见读法猜」 |
| **备课** | 不变：Sonnet 5.5 加结构化输出。但读音字段由本机流水线先填好，Claude 只补意思、难点，以及对「待确认」词给理由；每个读音带 `source` 和 `needs_review`；程序规则：来源是模型且是专有名词 → 强制待确认 | YOMI-Bench 显示 Claude 选读音的题最弱；读音来源可追溯，才能「核对课程、不一致按笔记改」 |
| **问老师** | 现有做法加一个 `lookup_reading` 工具；守则加两句：不断言音高重音、不说资料里没有的歌曲事实（发行、背景） | 先查后说；这两类没有评测数据，最容易编 |
| **语音识别运行时** | 接 **transcribe.cpp**（MIT，Metal，官方 Rust 绑定），不只接 whisper-rs；仍按 PRD 第一次用时下载模型、核对 SHA-256 | 一套代码能 A/B Whisper-turbo、Qwen3-ASR、SenseVoice；Handy 本身已经换到它 |
| **问老师的识别** | Whisper-turbo 和 Qwen3-ASR-0.6B / 1.7B 用自己的声音 A/B（20–50 条中文夹日语）；提示只放本句或本首的几个关键外语词，不放整首歌词；先过 VAD；输出和提示高度重合就丢掉 | Whisper 混说弱、会翻译；整首歌词当提示会被原样吐出来 |
| **检查念歌词** | 两路：① ASR 文字（固定语种，不给歌词）转读音逐字比对；② 日语用平假名 CTC、其他语言用 xlsr-espeak 音素 CTC，对歌词读音强制对齐，给每个音拍打分。两路都认为错才标橙；低置信度不判，改提示「再听一遍原唱」；加「我觉得我念对了」按钮，记下来调阈值 | 单靠 ASR 会把错音「纠正」掉；CAPT 研究说误报伤学习 |
| **发音评分服务** | 不用云端（Azure、SpeechSuper） | 要上传录音，和 PRD 冲突；日韩也没有音素级 |
| **唱** | 维持只看音高和节奏；可选：用 Qwen3-ASR 转写清唱，和歌词模糊匹配，只报漏句 | 唱歌发音打分没有可用方案 |
| **对齐** | 用户录音（干声）按句用 **Qwen3-ForcedAligner-0.6B** 出逐字时间（ONNX + ort）；原唱继续用现有智能对齐，以后再评估换不换；MFA 只在开发时做精度基准 | 本机能跑、Apache-2.0、偏差 43 ms，比 WhisperX 好三倍 |
| **老师开口** | 豆包 2.0 继续当主力。老师说的话里，日语词一律写成 `原文{读音}`（如 `夏実{かじつ}`）：屏幕显示原文加注音，送合成只送读音。先实测「中文音色整句加 `explicit_language=ja`」（现在的做法）和「日语段换 Hana / Bonnie 再拼接」哪个更自然。合成结果按句永久存本地（已有 tts-cache）。备用：macOS 语音；要换云端时选 MiniMax（有假名读音词典） | 豆包 2.0 没有日语读音标签，只能送假名；现在没假名的日语汉字词会被按中文念 |
| **互动** | 在「一句一循环」上加：你念的 / 原唱并排回放；整段连唱时先只放伴奏让人自己接；注音分层（假名 + 罗马音 → 汉字 + 注音 → 原文）；学过的句子间隔复现；每次学完一张小结（修好了哪几处、下次先练哪句） | 有产品验证和研究支持，而且和现有设计不冲突 |
| **授权** | 不用：espeak-ng、phonemizer、pykakasi、kakasi、korean-romanizer（GPL）；MMS 对齐权重（CC-BY-NC）；whisper-timestamped、aeneas（AGPL）；F5-TTS 权重（NC）。FunASR 系权重和 IndexTTS 用之前读原文 | 仓库是 MIT 开源 |

### 7.2 先做哪几步

1. **录一套自己的测试集**（半天）：20–50 条「中文夹日语」问老师的话，30–50 条念《夏実》歌词（含故意念错的），几句清唱。后面每一步都靠它定。公开数据里没有中日混说基准。
2. **读音流水线**（Rust，新文件 `src-tauri/src/learn/reading.rs`）：Lindera 加 sudachi.rs 出读音和「是否一致 / 未知词 / 专有名词」，接到备课和 `lookup_reading` 工具上。这一步不需要下载语音模型，马上能提升备课质量。
3. **老师输出 `原文{读音}`**：改守则和 TTS 送字逻辑，再实测豆包两种念法。改动小，直接修掉「日语汉字词被按中文念」。
4. **语音识别**：接 transcribe.cpp，用第 1 步的测试集 A/B Whisper-turbo 和 Qwen3-ASR，定问老师用哪个模型。
5. **念歌词的第二路**：平假名 CTC 加强制对齐打分，用测试集定「过了」的阈值（PRD 的待定项）。
6. **互动补齐**：并排回放、先回想、小结、间隔复现。

### 7.3 PRD §4.12 要改的地方（只列建议，没有改 PRD）

1. **「备课」**加一条：读音先由本机读音流水线填，每个读音带来源（笔记 / 歌曲标注 / 分析器 / 模型）和「待确认」标记；Claude 不单独决定读音。
2. **「语言组合」**韩语那条：「韩语给罗马音」改成「韩语给**按发音规则变化后**的读音和罗马音」（연음等），否则照着罗马字唱会错。
3. **「语音识别」**：
   - 引擎从「whisper.cpp（whisper-rs）」改成「transcribe.cpp（Rust 绑定，可换模型）」；
   - 模型从「Whisper large-v3-turbo」改成「Whisper-turbo 和 Qwen3-ASR 实测后二选一」；
   - 问老师「把这首歌的歌词当提示」改成「只放几个关键外语词」，并加「识别结果和提示高度重合就丢弃」；
   - 检查念歌词加第二路（假名 / 音素对齐打分），写明「两路都错才标、低置信度不判」。
4. **「风险」**那句的「换专门处理混说的模型」可以写具体：SenseVoice（中英混说最好，但日语弱）或 Qwen3-ASR。
5. **「老师开口说话」**：
   - 「混说」一条的例子 `<ja>なつみ</ja>` **本身用了错读**（应为 かじつ），且建议改成 `原文{读音}` 的写法：显示原文加注音，合成只送读音；
   - 「待查：豆包的计费单价、并发限制」填上：3 元/万字符，默认 10 并发，加购 100 元/并发/月（2026-11-13 官方计费页）；
   - 加一句：豆包 2.0 不支持 SSML，日语读音只能靠送假名控制。
6. **「一句一循环」**：
   - 第 2 步「念」加「你念的 / 原唱」并排回放；
   - 「一段里的句子都过了 → 整段连唱」加「先只放伴奏，自己接」；
   - 加注音分层、间隔复现、学完的小结。
7. **「AI 调用」**：费用估算注明依据，即 Sonnet 5.5 输入 $2、输出 $10、缓存读 $0.10 每百万 token（2026-11-13 官方价目）。
8. **加一条「授权」**：列出 7.1 最后一行不能用的组件。
9. **加一条「歌词注音来源」**：歌词站注音（utaten 等）只能由用户在本机导入或手动粘贴，不内置、不批量抓取（版权，仓库公开）。
